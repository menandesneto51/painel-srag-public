# v2.10 — Gate de Implementação e Merge\n\n## Objetivo\n\nVerificar uma implementação realizada manualmente em branch separada antes de declará-la elegível para consideração de merge humano.\n\n## Regra central\n\neligible_for_human_merge != merge executado.\n\n## Evidências obrigatórias\n\n- implementation_package_id v2.9;\n- branch de implementação não protegida;\n- commit-base idêntico ao pacote v2.9;\n- commit de implementação diferente do commit-base;\n- changed_paths contidos no escopo autorizado;\n- diff review;\n- scope review;\n- CI;\n- testes de regressão;\n- backtesting para mudanças de lógica;\n- revalidação epidemiológica;\n- revalidação estatística quando aplicável;\n- revisão de segurança/privacidade;\n- critérios de aceitação;\n- verificação do rollback.\n\n## Decisões\n\n- eligible_for_human_merge;\n- blocked;\n- defer.\n\n## Mudança documental\n\nPara proposal_type=documentation, backtesting e revalidação estatística podem ser not_applicable.\n\n## Proteções\n\n- merge_eligibility_is_not_merge=true;\n- automatic_commit_enabled=false;\n- automatic_merge_enabled=false;\n- automatic_deploy_enabled=false;\n- human_merge_required=true;\n- human_review_required=true.\n\n## Diff autorizado\n\nTodo arquivo alterado deve estar explicitamente listado em target_paths do pacote v2.9. Diretórios somente autorizam descendentes quando target_paths termina com /.\n\n## Próximo passo\n\nApós eligible_for_human_merge, uma pessoa revisa a PR/branch e decide explicitamente sobre o merge. Deploy continua fora deste gate.\n
